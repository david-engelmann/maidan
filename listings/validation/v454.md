## What passed

- `initialize` negotiation for every supported revision (2026-07-28,
  2025-11-25, 2025-06-18, 2025-03-26), and an unknown revision is offered the
  newest.
- On both `/mcp` and `/mcp/streamable`:
  - `tools/list` returns 265 tools, and the SDK accepts every schema;
  - `whoami` authenticates as the bearer;
  - resources list, read and templates, and prompts all answer.
- One valid and one invalid call per tool group, 34 groups (33 that take
  arguments, plus `whoami`). Each invalid call's error names the argument it
  got wrong.

The checks match v441's, with one new group and two new tools since then.
The full output is in the run's log; every line reads `ok`.

## Identity and tokens

- **Token used:** the admin bearer that `maidan init` mints on a throwaway
  database, which is never a listing's token.
- **Reviewer token:** not checked. Directory reviewers start their own
  sandbox at try.maidan.world, which serves `v454.0.0`, so a reviewer token
  is minted only if a directory asks for one.

## Protocol-layer properties

Unchanged since `v441.0.0`, and held by the same tests:
- nobody accepts their own approval request;
- a gate is accepted only by a signed-in person's session or `approval:grant`;
- the close gate is a durable store row that an elicited client answer never
  decides.

## Trust model

Provider-rendered approval UI is untrusted display, the Maidan console is the
trust root, and an approval whose evidence the human did not see in the
console is provisional. It appears in `docs/Listing.md` and
`crates/maidan-server/tests/cursor_plugin_manifest.rs`.
