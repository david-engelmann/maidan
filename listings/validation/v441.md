## Protocol-layer properties

Not probed by this run; each is a server property tested at this commit, and
the suites holding these tests passed on `4eb24c20`.

- No surface lets the supervised agent compose, trigger or satisfy its own
  approval: `nobody_accepts_their_own_request` (`approval_decide_e2e`),
  `no_one_accepts_their_own_approval_request` (`attestation_e2e`) and
  `self_approval_laundering` (both backends).
- Every approval binds to a verified human identity, per-user credentials at
  minimum: since #1325 a gate is accepted only by a browser session the person
  signed in to or `approval:grant`
  (`a_plain_human_bearer_gets_the_confirmation_path_not_an_acceptance` and
  `the_link_is_confirmed_once_by_the_bound_persons_session`, `approval_decide_e2e`).
- The close gate stays server-side and durable: the gate is a store row on both
  backends (`approval_gate_e2e`), and an elicited answer from a client never
  decides it (`a_client_with_url_elicitation_is_asked_to_open_the_link`).

## Trust model

The listing's materials and tests carry this sentence: Provider-rendered
approval UI is untrusted display, the Maidan console is the trust root, and an
approval whose evidence the human did not see in the console is provisional.

- Where it appears: `docs/Listing.md` (the Cursor listing) and
  `crates/maidan-server/tests/cursor_plugin_manifest.rs`. Each listing's own
  record names where it appears in that listing.
