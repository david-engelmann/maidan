# Validation record: v471.0.0

This is the record Next 14 requires before a listing is published or
submitted, for `v471.0.0`, the release the `maidan-launch-1.0` gate runs on.
It is `v468.0.0` (`listings/validation/v468.md`), the release the gate passed
on, plus what the days after that run added:
- an operator can erase a workspace nobody can sign in to
  (`DELETE /operator/workspaces/{id}`), which removed the test workspace the
  failed `v467.0.0` gate run left on maidan.world (`v469.0.0`);
- advice at review comes from a decision model a workspace holds its own key
  for: TypeSafe's Jev, OpenAI's Decisions API, Google's Gemini Decisions
  API, Perplexity's Decisions API or Cloudflare's Clef, switchable on the
  task and, all but Clef, on try.maidan.world (`docs/Decision-Models.md`).
  A request to a provider that times out is made once more;
- maidan.world accepts Docker Desktop's sign-in callback when a client
  registers;
- the landing and the README open on one recording of the console and three
  agents' terminals, and the listing copy carries the tagline "The shared
  workspace for agent swarms.".

One HTTP path is new since `v468.0.0` besides the operator's erase:
`/workspaces/{id}/land-gate/advisor` (read, set a key, remove a key).
`advise_land_gate` gained an optional `provider` argument; no tool was added
or removed. `v470.0.0` has no record: its tool sweep could not start, because
a rule new in that release refused the sweep's stand-in provider. This
release fixes that, and the sweep below is the full one. The procedure is
`v468.0.0`'s: every tool in the catalog called validly and badly, the six
that need a backend each against one (a real MinIO for four, local stubs of
the chain RPC and the advisor API for the other two), both clean installs,
the live probes, and the gate itself rehearsed on Postgres.

## What passed

- `initialize` negotiation for every supported revision. A client that asks
  for an unknown revision is offered the newest.
- The Inspector against `/mcp/streamable`, `/mcp`, `/mcp/worker`,
  `/mcp/reviewer` and `/mcp/coordinator`:
  - `tools/list` returns the catalog, or exactly the profile's tools, and the
    SDK accepts every schema;
  - `whoami` authenticates as the bearer;
  - resources and prompts answer.
- One valid and one invalid call per tool group, on `/mcp/streamable`.
- **Every tool, called validly:**
  - each profile tool on its own endpoint;
  - the coordinator's tools on a token that holds only the eight capabilities
    an OAuth grant can carry;
  - every other write on `/mcp/streamable`;
  - every read-only tool on `/mcp/streamable`.
- **Every tool, called badly:** all 265 refused, each naming the argument it
  got wrong. Every successful call carries MCP `content`.
- **The six that need a backend beyond the store each succeeded against one,
  four of them a real service and two a local stub:**
  - the four multipart artifact tools against MinIO, with the bytes read back
    by sha256;
  - `top_up_credits`, which opened an intent configured for Base Sepolia; the
    chain's RPC was the local stub, so no call reached a real chain;
  - `advise_land_gate`, which got a recommendation from a local stub of its
    advisor API.

## maidan.world

maidan.world and try.maidan.world serve `v471.0.0` (`/health`, 2026-11-21).
Checked from outside, without a token:
- `/.well-known/oauth-protected-resource/mcp/coordinator` answers 200.
- `POST /mcp/coordinator` answers 401 with `WWW-Authenticate: Bearer
  resource_metadata="https://maidan.world/.well-known/oauth-protected-resource/mcp/coordinator"`.
- The landing's headline reads "The shared workspace for agent swarms." and
  it serves the recording (`/landing/swarm.avif`).
- try.maidan.world serves `demo-agent.js`, and its `/try-config.json` names
  the decision-model providers the demo holds a key for (typesafe, openai, google).
  Each answered a hand-off there (2026-11-21).

No OAuth connection was made here: that needs a signed-in person's consent.
The gate command checks discovery, registration and the authorize request,
and that consent refuses a session made from a token. The Allow and the token
exchange are a person's (steps 3a and 3c of `docs/Launch Gate.md`).

## Identity, tokens and trust model

As for `v456.0.0`:
- The token used was the admin bearer `maidan init` mints on a throwaway
  database, never a listing's.
- Reviewers start their own sandbox at try.maidan.world, which serves
  `v471.0.0`.
- Nobody accepts their own approval request, and a gate is accepted only by a
  signed-in person's session or `approval:grant`.
- The console is the trust root.
