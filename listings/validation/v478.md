# Validation record: v478.0.0

This is the record Next 14 requires before a listing is published or
submitted, for `v478.0.0`, the release maidan.world and try.maidan.world run.
It is `v474.0.0` (`listings/validation/v474.md`) with:
- two sentences changed on the try page (`v475.0.0`).
- a federation peer's secret that reads only the log of the workspace it is
  registered in (`v476.0.0`).
- the server's own GitHub, Slack and Linear credentials serving only the
  workspaces the operator opened (`v477.0.0`).
- a workspace that connects its own GitHub, Slack and Linear, receives its own
  inbound events on its own URLs and manages its outbound webhooks in the
  console, links that belong to a workspace, live streams that check each
  event against the subscriber when it is sent, share tickets that never open
  direct messages, digests and run counts that keep to what the reader may
  read, and a federated mention that notifies only members of its own
  workspace (`v478.0.0`).

`v475.0.0`, `v476.0.0` and `v477.0.0` have no record of their own. Each was
replaced within a day. The gate command passed against maidan.world on
`v473.0.0` on 2026-11-22 and on `v478.0.0` on 2026-11-24 (each 75 passed, 0
failed, 0 skipped).

Routes differ from `v474.0.0`. `GET /workspaces/{wid}/connections` is new,
and so are `PUT` and `DELETE` on `/workspaces/{wid}/connections/{surface}`,
each with a console twin under `/ui/api`. So are `POST
/workspaces/{wid}/connections/github/webhook`, `POST
/workspaces/{wid}/connections/slack/events` and the console's `GET`, `POST`
and `DELETE` on `/ui/api/workspaces/{wid}/webhooks[/{id}]`. No MCP tool was
added or removed. The procedure is the same. Every tool in the catalog was
called validly and badly, the six that need a backend each against one (a real
MinIO for four, local stubs of the chain RPC and the advisor API for the other
two), and both clean installs, the live probes and the gate rehearsed on
Postgres followed. This record adds probes on the released binary for what the
release fixed.

## What passed

- `initialize` negotiation for every supported revision. A client that asks
  for an unknown revision is offered the newest.
- The Inspector against `/mcp/streamable`, `/mcp`, `/mcp/worker`,
  `/mcp/reviewer` and `/mcp/coordinator`:
  - `tools/list` returns the catalog, or exactly the profile's tools, and the
    SDK accepts every schema.
  - `whoami` authenticates as the bearer.
  - Resources and prompts answer.
- One valid and one invalid call per tool group, on `/mcp/streamable`.
- **Every tool, called validly:**
  - each profile tool on its own endpoint,
  - the coordinator's tools on a token that holds only the eight capabilities
    an OAuth grant can carry,
  - every other write on `/mcp/streamable`,
  - every read-only tool on `/mcp/streamable`.
- **Every tool, called badly:** all 265 refused, each naming the argument it
  got wrong. Every successful call carries MCP `content`.
- **The six that need a backend beyond the store each succeeded against one,
  four of them a real service and two a local stub:**
  - the four multipart artifact tools against MinIO, with the bytes read back
    by sha256,
  - `top_up_credits`, which opened an intent configured for Base Sepolia. The
    chain's RPC was the local stub, so no call reached a real chain.
  - `advise_land_gate`, which got a recommendation from a local stub of its
    advisor API.

## Probes on the released binary

Each ran on 2026-11-24 against the released `maidan-server` on a throwaway
SQLite database, except the fourth.

**Two tenants and a peer.** An admin of one workspace registers a peer that
names another workspace. The peer's secret is refused with 403 on that
workspace's event log, full snapshot, verify, catch-up and snapshot. The same
secret reads its own workspace's log with 200.

**The server's own credentials.** The server held instance GitHub and Slack
credentials. A sandbox workspace's admin blessing a GitHub repository,
blessing a Slack channel, linking a Slack channel, linking a GitHub issue and
watching a pull request each answered 400 with `connect GitHub for this
workspace first (Tools, Integrations)`, or the same with Slack. The
workspace's allowlist stayed empty.

**Streams, connections and share tickets.** Nine checks, nine passed:
- A member outside a direct message who names the DM channel in
  `channel_grants` receives nothing of it over `/ws/subscribe`, live or on
  replay. A participant receives it, and the outsider's stream is shown live by
  a public message.
- `GET /workspaces/{wid}/connections` lists github, slack and linear with
  inbound URLs on the public origin.
- A synthetic GitHub token is refused with 400 and GitHub's own reason.
- A sandbox cannot bless a GitHub target.
- An unsigned post to a workspace's inbound GitHub URL answers the same 404
  for an unknown workspace and for one with no connection.
- No answer carries the token.
- A share ticket for the DM channel is refused with `direct messages are not
  shared by ticket`.

**A hosted instance on Postgres.** On an instance running the release's
commit, GitHub, Slack and Linear each refused a synthetic token with 400 and
the provider's own reason.

**The console's Integrations tab.** `ui-tests/tests/console-connections.spec.ts`
drives it in a real browser against the real server. Its nine tests run in the
`ui tests (playwright)` job on every merge. A refused token shows the
provider's reason. A connected account shows its inbound URL, and the token
appears in neither the page nor any console API answer. A webhook's signing
secret is shown once. Nothing scrolls sideways at 390 px.
