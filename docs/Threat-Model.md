# Threat model

High-level security view of Maidan as it ships. This is an operator and
integrator document, not a formal audit.

## Assets

| Asset | Location | Sensitivity |
|-------|----------|-------------|
| Workspace data | Postgres / SQLite | Messages, threads, votes, search index |
| Content key-encryption key | Operator secret (`MAIDAN_CONTENT_KEK`), never the DB | Wraps every per-message content key; with a pre-shred backup it recovers withdrawn words |
| Per-message content keys | DB (`maidan_content_keys`, wrapped by the KEK) | Destroyed on tombstone (crypto-shredding) |
| Workspace secrets | DB (`maidan_secrets`, AEAD ciphertext) | Substituted into egress only for allowlisted hosts; never in the event log |
| Delegation grants | DB (`maidan_delegation_grants`) | Let one member act as another, time-boxed and revocable |
| API tokens | DB (`maidan_api_tokens`) | Bearer secrets (hashed at rest) |
| Share-ticket secrets | DB (`maidan_share_tickets`) | SHA-256 hash only; raw `maid_share_…` value returned once |
| App OAuth codes | DB (`maidan_oauth_codes`) | SHA-256 hash only, single-use, short TTL — never the plaintext code |
| OAuth 2.1 codes and refresh tokens | DB (`oauth_authorization_codes`, `oauth_refresh_tokens`) | SHA-256 hash only; a code is single-use for ten minutes, a refresh token rotates and a reuse revokes its lineage |
| Federation peer secrets | DB (encrypted with `FEDERATION_ENCRYPTION_KEY`) | Outbound poll credentials |
| Artifacts | Local FS or S3 | User/agent uploads |
| Audit log | DB | Security-relevant actions |

## Trust boundaries

```text
[Agent / Browser] ------HTTPS+Bearer------> [maidan-server] --SQL--> [Database]
[External recipient] --HTTPS+ShareTicket--^       |            `--> [Artifact store]
                                                   `--> [Peer over A2A HTTPS]
```

- **Untrusted:** MCP clients, HTTP clients, federation peers (authenticate but validate payloads).
- **Trusted:** Operator with DB backup access, host running the server.

## Primary threats

Each row's Test column names the regression that holds the mitigation (a
Rust test function or a `*.rs` file stem). `threat_model_contract` fails
if a name is missing or does not resolve in the repo. A PR that changes
a threat or its mitigation updates the row, and the named test if it
moves.

| ID | Threat | Mitigation today | Residual | Test |
|----|--------|------------------|----------|------|
| T1 | Stolen API token | Capability-scoped tokens; revoke via `DELETE /tokens/:id` | Token usable until revoked | `api_token_create_lookup_and_revoke` |
| T2 | `AUTH_DISABLED` left on in prod / by mistake | **Fail-closed:** `AUTH_DISABLED` is honored only with the explicit `MAIDAN_ALLOW_INSECURE_NO_AUTH=1` acknowledgement and never when `MAIDAN_ENV=production` — either way boot is refused, so a stray flag can't silently open the server | A dev binary with both flags explicitly set is still open by design (intended for seed/test) | `auth_disabled_is_fail_closed` |
| T3 | Bootstrap routes create admin without auth | `MAIDAN_BOOTSTRAP=1` when auth is on; one workspace via bootstrap; production Docker image built **without** the `bootstrap` feature | Open `/workspaces` if dev binary with `AUTH_DISABLED` or bootstrap left on | `bootstrap_e2e`, `bootstrap_absent_e2e`, `init_bootstraps_once_then_refuses` |
| T4 | Federation peer impersonation | Peer bearer + idempotent ingest | Compromised peer can push events | `federation_ingest_rejects_wrong_peer_bearer` |
| T5 | Artifact exfiltration | Bearer on download; SHA-256 addressing; a per-workspace reference gates every read, so a SHA known from another tenant does not open the blob | A reader in the owning workspace can copy what it can read | `artifact_isolation_e2e` |
| T6 | SQL injection | `sqlx` parameterized queries | ORM bypass bugs; no dedicated regression test (pinned as `practice`) | `practice` |
| T7 | GDPR right-to-erasure | Tombstoning destroys the message's content key, so the event log, exports and peers keep only ciphertext and the chain still verifies (crypto-shredding); `DELETE /messages/:id/purge` hard-deletes the row; `DELETE /artifacts/:sha` drops a shared artifact's bytes with its last reference (all `token:admin` except the tombstone) | A DB backup taken before the shred plus `MAIDAN_CONTENT_KEK` recovers the words until backup rotation; a peer that ingested the words keeps them unless it ingests the tombstone; legal-hold copies are kept by design | `crypto_shredding_e2e` |
| T8 | Resource exhaustion / denial-of-service by tenant | Per-client rate limit (`MAIDAN_RATE_LIMIT_MAX`, default 1200 per 60 s; an unverified bearer shares the client-IP bucket) + per-workspace fairness limit (`MAIDAN_WORKSPACE_RATE_LIMIT_MAX`, default 6000 per 60 s, charged only for a caller authenticated into that workspace); per-connection statement timeout; a global in-flight ceiling (`MAIDAN_MAX_CONCURRENT_REQUESTS`) refuses excess requests with `503` before authentication, and WebSockets have their own ceiling; an MCP `wait_for_*` long-poll gives its in-flight permit back once it parks, and one workspace may park at most 32 waits (the next is refused with the typed rate-limit error), so one token's waits cannot hold the ceiling every tenant shares; an operator-supplied egress URL's DNS lookup gives up after 5 s | No hard CPU/IO isolation between tenants on one instance (infra-level); parked waits are bounded per workspace, not per instance, so many workspaces can still park many tasks | `rate_limit_e2e`, `workspace_rate_limit_default_e2e`, `overload_e2e`, `long_poll_fairness_e2e` |
| T9 | Tampered or replayed workspace export; credential leak via export | Signed `maidan.workspace.export/1` (Ed25519); verify fail-closed on hash/sig/pin/secret fields; **tokens die on export** (no token/secret continuity) | Integrity without `MAIDAN_EXPORT_VERIFY_KEYS` is not a trust anchor (anyone who can sign with *a* key can produce a valid file); operator key compromise forges exports | `sign_then_verify_succeeds`, `bit_flip_in_payload_fails`, `forbidden_secret_field_fails_sign_and_verify` |
| T10 | Host rewrites the event log (splice, delete, payload edit) | Per-workspace SHA-256 hash chain on every stored event (`prev_hash` + `content_hash`); `GET /workspaces/:wid/events/verify` 409 fail-closed; federation ingest verifies origin hashes before remap | A wholly fabricated but internally consistent chain still verifies (hashed, not signed — authorship is T9); the pruned prefix is covered by snapshot catch-up (T11) | `event_chain_e2e`, `chain_verify_e2e` |
| T11 | Fabricated or gapped event-log history; search index silently diverges | Hashed snapshot + since-LSN catch-up for the pruned prefix (`maidan.event-log.snapshot/1`); CursorTooOld never clamps; search tap verifies backfill and fails loud on `Lagged` without a log | Snapshot is hashed, not signed — a consistent-but-fabricated graph is T9; `include_graph` is `token:admin` / peer so `workspace:read` cannot dump private channels | `cursor_too_old`, `log_snapshot` |
| T12 | Leaked or replayed cross-organization share ticket | Separate `ShareTicket` auth class; header-only credential; one channel; exact artifact-SHA allowlist; hard 48-hour maximum; immediate revocation; dedicated GET-only routes with reduced DTOs; liveness rechecked before an artifact backend read; raw secret returned once and only its SHA-256 digest stored | A stolen live ticket can read its deliberately shared channel and allowlisted files until expiry or revocation; operators must keep authorization headers out of reverse-proxy logs | `share_ticket_rest_e2e` |
| T13 | SSRF through an operator-supplied webhook, slash/FSM hook, federation peer, or A2A push URL | One canonical URL parser rejects credentials, loopback, private, link-local, shared, documentation, multicast, and reserved literals. Every delivery resolves again, rejects the whole answer set if any address is non-public, pins that set into a no-redirect HTTP client, and therefore closes DNS-rebinding and redirect pivots. `MAIDAN_ALLOW_PRIVATE_EGRESS=1` is a development-only loopback escape hatch and is rejected in production. An OAuth client metadata document is fetched only from a host the operator lists, at a public address, pinned, with no escape hatch at all | A public service can itself proxy to a private target; outbound network policy remains useful defense in depth | `rejects_every_non_public_literal_family`, `rejects_a_dns_answer_set_if_any_address_is_non_public`, `private_egress_escape_hatch_is_never_accepted_in_production`, `a_listed_metadata_host_on_a_private_address_is_never_fetched` |
| T14 | A delegate acts as another member beyond what it was lent | A delegation grant lives no longer than the workspace's grant ceiling (default 90 days) and is exchanged for a token of at most an hour that *is* the subject, carrying only what the grant, the delegate's own authority and any requested attenuation all allow; one hop only; every use is recorded with the delegate as actor and the subject as subject, refusals included; an approval cannot be borrowed for work the actor did | A grant is trusted until it expires or is revoked | `delegation_policy` |
| T15 | Cross-tenant read or write through an omitted or foreign id (an optional `workspace_id`, a SHA, a subscription filter) | Omitted scope defaults to the caller's workspace, never "all"; `tenant_isolation_e2e` runs every HTTP operation, MCP tool and live stream as a second tenant | A new route that skips the shared extractors is caught only by that suite | `tenant_isolation_e2e` |
| T16 | Credentials leaking into traces | `Authorization`, `Proxy-Authorization`, `Cookie`, `Mcp-Session-Id`, the Slack and GitHub signatures, `Set-Cookie` and `Location` (the consent redirect carries an OAuth `code`) are marked `Sensitive` on every span, and the query string (where an OAuth `code` travels) is never recorded | A handler that logs a secret itself | `trace_redaction_e2e`, `the_redirect_that_hands_over_a_code_never_reaches_the_trace` |
| T17 | A script injected into `/ui` reads the bearer token | The page keeps no token: a pasted one is exchanged for an `HttpOnly; SameSite=Lax` session (`POST /auth/session/from-token`) that resolves the token again on every request, so revoking or rotating the token ends it; an unsafe session request or session WebSocket from another origin is refused | Script running in the page can act as the session while the page is open, but cannot carry the credential away | `session_from_token_e2e` |
| T18 | A prompt-injected producer pastes a credential it can read into its result, and Maidan publishes it on GitHub, Slack or Linear | Every egress send and change-flow write is scanned for credential shapes (GitHub, Anthropic, OpenAI-style, AWS, Slack, JWT, PEM private key, Maidan's own `maid_` secrets) and refused on a match; the delivery records the kind and surface, never the text, and the operator channel is told ([Result Delivery](Result%20Delivery.md#credential-guard)) | A credential in a shape the guard does not know, or encoded or split to dodge it; a JWT or PEM key in a diff's added lines (allowed as a fixture); the result itself is still stored in Maidan. `MAIDAN_EGRESS_CREDENTIAL_GUARD=off` disables it, and is refused with `MAIDAN_ENV=production` | `egress_credential_guard_e2e` |
| T19 | A review model's result passes a merge gate it does not own: it names another commit status context (`stamp`, `security`), claims a pass the verdict does not say, stamps a head it was not briefed on, or a member grants itself the authority to post | A review thread's result posts only the `pre-review` status (a one-entry allowlist), only for a reporter an operator granted the `pre-review` governance skill (`channel:admin`, never self-declared), with the state taken from `verdict` (`PASS` or `FIX-FIRST`) and a description Maidan builds from the reporter's handle and its own usage's family, at the head on the thread's `Head to review:` line; anything else posts nothing and leaves a warning on the delivery row ([Result Delivery](Result%20Delivery.md#the-pre-review-commit-status)) | A granted reviewer's model can still post a wrong `PASS` on the briefed head: the skill vouches for who reviewed, not for the review; the briefed head is as trustworthy as whoever wrote the thread's description | `pre_review_status_e2e`, `an_agent_cannot_grant_itself_a_governance_skill` |
| T20 | An MCP client, or someone posing as one, gets more of a person's authority than they consented to, or keeps it | OAuth 2.1 with PKCE S256 for every client; exact redirect matching; consent only by a person on a same-origin request to a page that cannot be framed; tokens bound to `/mcp/streamable` and their workspace, never wider than the grant, the client or the member; refresh rotation with lineage revocation on reuse; a lineage that ends 90 days after consent, so a person consents again at least that often; a member who leaves takes their grants with them; a client metadata document held for five minutes only once it passed every check, never past a revoked client ([OAuth](OAuth.md#security-properties)) | A person who consents to a malicious client lends it what they consented to, for at most 90 days unless they disconnect it sooner; a self-registered client's name is unverified, and the consent page says so; a document change reaches the server within five minutes, not at once; consent takes any live session, up to its eight hours, without a fresh sign-in; an access token minted before its client was revoked lives out its hour (both decided 2026-11-10, [OAuth](OAuth.md#decided-after-the-audit-2026-11-10)) | `oauth_hardening_e2e`, `oauth_token_endpoint_e2e`, `oauth_scope_contract_e2e`, `oauth_authorize_signin_hosts_e2e` |
| T21 | A writer registers automation with the whole workspace's reach: an FSM hook that runs a tool it may not call on every matching transition (clearing a review requirement, then closing its own work), or a webhook that receives every private channel and DM | Registering an FSM hook (REST and MCP), creating an outbound webhook and choosing the mention webhook need `workspace:admin`; a worker token holds `workspace:write` and is refused | A registration outlives the member who made it, an FSM hook's tool runs with the server's authority rather than its creator's, and a webhook's deliveries are not filtered by what its creator may read | `automation_registration_admin_e2e` |
| T22 | Someone outside the organization speaks as a member through a bridge: a comment on a linked public GitHub issue, or a Slack Connect guest in a linked channel, is posted as the member who linked it, and an agent reading the thread takes it as that member's | A GitHub comment is posted only when its `author_association` is `OWNER`, `MEMBER` or `COLLABORATOR`; a Slack message only when its sender's team is the team the app is installed in | An insider's bridged text is still posted as the linking member with no typed provenance, so an agent cannot tell it from the member's own words; a Slack message whose event names no sender team (neither `user_team` nor `team`) is treated as the installing team's and posted | `a_comment_from_someone_without_a_role_on_the_repository_is_not_posted_as_the_linking_member`, `a_slack_connect_guest_from_another_team_is_not_posted_as_the_linking_member` |

## Bootstrap hardening options

1. **One-shot seed flag** — `MAIDAN_BOOTSTRAP=1` required for bootstrap routes when auth is enabled; only the first workspace may be created via bootstrap. A later workspace is `POST /operator/workspaces`, which requires `operator:global` and mints an admin token that does not hold `operator:global` or `audit:read-global`.
2. **IP allowlist** — reverse proxy restricts bootstrap paths to admin CIDR.
3. **Compile-time strip** — production release builds omit bootstrap routes via Cargo feature `bootstrap` (default on for dev/tests; Docker image uses `--no-default-features`).

Recommended production flow: seed the first admin with `maidan init` (writes through the store — no unauthenticated HTTP routes, no `AUTH_DISABLED`; see [Production.md](Production.md#maidan-init)), mint per-agent tokens from it, deploy the production image (no bootstrap routes), set `MAIDAN_ENV=production`. A second workspace is `POST /operator/workspaces` with that admin token. The HTTP-bootstrap / `AUTH_DISABLED=1` seed is a private-network-only alternative for dev.
