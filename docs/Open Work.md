# Open work

The one live list of what is being built, what comes next, and what is waiting
on a decision. Last reconciled against `main` at `0a719339` (2026-10-03).

**The rule.** A shipped item is deleted, not struck through: its record is the
CHANGELOG entry and the PR. A wrong row is corrected in place, never answered
by a new row beside it. Nothing in **Now** or **Next** is marked done. Feature
PRs do not edit this file; the coordinator reconciles it after merges, because
every PR editing its own row made every PR conflict with every other.
`scripts/check-open-work.sh` (CI job `open work`, not required) runs on `main`
and on a PR that edits this file, and fails when a PR listed under **Now** has
merged or the stamp above is not on the branch. Red on `main` means reconcile.

History (the dated programs, audits and dispositions this file carried until
2026-09-29) is in [Open Work 2026-08-25 to 2026-09-28](archive/Open%20Work%202026-08-25%20to%202026-09-28.md).
Direction is in [Roadmap](Roadmap.md); what shipped is in
[Capabilities](Capabilities.md) and `CHANGELOG.md`.

## Known risks

| Risk | Mitigation | Residual | Watched by |
|---|---|---|---|
| A pasted bearer token lives in `localStorage` | Tokens are capability-scoped, revocable and rotatable (#1116); #1093 escapes the page's `innerHTML` writes; #1142 exchanges the token for an `HttpOnly` session; `/ui` sends a Content-Security-Policy (#1213) | A script injected into the page can act as the session while the page is open but cannot take the credential away (Threat-Model T17) | #1142, #1213 |
| Admin merges while branch protection is not strict (F-43, kept off on 2026-10-01) | The merge loop reads the checks of the PR's exact head commit, requires all eight required checks there and every CodeRabbit comment answered, merges with `--match-head-commit`, and first builds the PR merged onto current `main` and runs the static contracts | A break that only a full test run on the merged tree would catch; `main`'s own CI catches it after the merge | `main` CI; Process below |
| Events delivered at most once on the optimistic path | Transactional outbox, quarantine and replay; opt-in `at_least_once` delivery per `consumer_id` | A client that does not opt in can see a gap or a duplicate | `maidan_outbox_quarantined`, `MaidanOutboxQuarantined` |

## Process

**Merge discipline while branch protection is not strict (thread 43).** A PR
merges when every one of the eight required checks has passed on its exact
head commit and nothing else on that commit is queued, running or failed; the
merge names that commit (`gh pr merge --match-head-commit`), so a push in
between makes GitHub refuse it. Before merging, the PR is merged onto current
`main` locally and built, and the static contracts run on the result
(`attribution_scope_contract`, `authority_audit_contract`,
`http_operation_kinds_contract`, `docs_numbers_contract`,
`env_registry_contract`, `ui_js_contract`, `openapi_well_formed`, the event-kind
and lexicon contracts, `migration_register`, `backend_parity`). Stacked
branches rebase in dependency order, replaying only their own commits.
Two merges broke this on 2026-09-30 and are why the rules read as they do:
#1124 merged while `gh pr checks` still showed the previous commit's runs, and
#1133's last commit merged two seconds after a push, before GitHub reported the
new head. `main`'s CI passed on #1124's merge; #1133's is recorded in its PR.

**Open Work is the coordinator's.** Feature PRs do not edit this file or the
Roadmap; the coordinator reconciles them after merges, and the `open work` job
runs on `main` and on PRs that edit the file. The merge loop's pre-merge build
takes a lock that names its holder, and a lock whose holder is gone is taken
over: a killed loop once held every merge for five hours (2026-09-30).

**Review comments.** CodeRabbit reviews every PR (Decisions). Each top-level
comment is fixed, or answered with the reason it does not apply, before the
merge; the merge loop holds a PR while one has neither a reply nor
CodeRabbit's "Addressed in commit" marker. From 2026-09-28 to 2026-10-01 the
loops merged without that check, which is how 126 comments went unanswered
(75 of them valid, one a cross-tenant rate-limit bug).

**Old branches.** A branch whose work shipped another way, or was closed, is
kept as an `archive/<branch>` tag and then deleted (the six `cursor/*`
branches, 2026-10-01). Stashes are not left on the shared stack: they are
kept as local `refs/archive/stash/*` refs, which are never pushed because a
stash can hold untracked files.

**UI changes (thread 42, 46).** The PR template's `/ui` checklist is run by
hand before a UI PR is opened: the token path and the OIDC path, keyboard only,
a 390 px viewport, and every new string re-read.
