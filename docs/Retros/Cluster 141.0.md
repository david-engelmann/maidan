# Cluster 141.0 retro — Publish the docs/* pages

> Tag **`v141.0.0`**. Phase XXIV (post-gate hardening). No new gate tag.

## What shipped

- **`book/sync-docs.sh`**: stages the 21 SUMMARY-referenced `docs/*.md` into
  `book/src/docs/` (generated, gitignored) at build time, so mdBook builds
  them as real in-site pages. Also rewrites out-of-`docs/` repo-root links to
  absolute GitHub URLs and flattens Obsidian `[[wikilinks]]` to plain text.
- **`SUMMARY.md` / `introduction.md` / `api.md`**: dropped the `../` from the
  `docs/` links so they resolve under `/maidan/`.
- **`docs.yml`**: runs `book/sync-docs.sh` before `mdbook build book`.
- **`.gitignore`**: ignores generated `book/src/docs/` + `book/build/`.
- **`introduction.md`**: a copy-pasteable local quickstart on the landing page.
- **`book/src/404.md`**: a helpful custom 404 (home + integration guide; notes
  the `/maidan/` prefix whose absence produced the original 404).

## Surprises

- **mdBook fails silently on out-of-`src` SUMMARY paths.** No warning, no error
  — the `docs` CI job was green for the entire time the published site shipped
  ~20 dead sidebar links. A passing build is not evidence of a working site;
  the page count (27 vs ~6) and the absence of `../docs` escapes in the landing
  page are the real checks.
- **The 404 the user hit was generated by the nav itself.** From `/maidan/`,
  the sidebar's `../docs/Integration.html` resolved up-and-out to
  `…github.io/docs/Integration.html` — GitHub's user-level 404 — so the bug
  looked like "Pages isn't deployed" when the deploy was fine.

## Decisions

- **Build-time staging over relocating docs.** Keeps a single source of truth
  (`docs/`, GitHub-native) and gives mdBook real sources under `src/`, with no
  duplicated content committed.
- **Rewrite-on-stage for cross-tree links.** Repo-root links → GitHub URLs;
  wikilinks → plain text — both done in the sync script so the source `docs/`
  stay correct for github.com browsing.

## Risks identified + still open

- **No automated "links resolve" gate in CI.** The `docs` job builds but
  doesn't fail on dead links. A future link-check step (e.g. mdbook-linkcheck)
  would catch regressions; for now the warning-free build + page-count check is
  the guard. Logged for [[Open Work]].

## Forward look

The published docs now match what the sidebar promises. A link-checker in the
`docs` CI job is the natural follow-up to keep it that way.
