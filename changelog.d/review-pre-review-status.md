### A reviewed result posts a guarded `pre-review` commit status

- **Added:** a result on a review thread (`kind = review`) delivered to a `github` target also posts a `pre-review` commit status on the head the thread was briefed on (its `Head to review:` line), for a merge gate that reads one. `PASS` posts `success` and `FIX-FIRST` posts `failure`; the description, `PASS at <sha9> by <family> as <handle>`, is built by Maidan from the reporting member's handle and the provider family its own usage names, never from the model. Only the context `pre-review` is allowed, so a review cannot post a status another gate owns. A refused context, verdict or head, or a status GitHub does not take, posts nothing and is recorded on the GitHub row's `delivery_warnings`; the comment is delivered either way.
