### A fine-grained GitHub token gets CI notices through the Actions API

- **Fixed:** When GitHub refuses Maidan's token a pull request's check runs, the change sweep now reads the head's CI from the Actions and commit-status APIs instead. GitHub cannot give a fine-grained token check runs at all, so with one the check rollup came back `FORBIDDEN`, the sweep read that as "nothing has reported yet", and no `ci_failed` or `checks_done` notice ever fired (#1623). A fine-grained token now needs **Actions: read** and **Commit statuses: read**. Each workflow run counts as one check; a failed run is opened to its jobs, so the notice names the failing job and carries its log tail. Check runs from apps other than Actions aren't visible this way, and the "required check never reported" hold is off for such a read. When the token can't read either API, the sweep logs a warning and raises an ops alert naming the permissions it needs.
