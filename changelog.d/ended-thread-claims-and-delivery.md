### An ended task is not claimed again, and a cancelled change is not pushed

- **Fixed:** `POST /threads/{id}/assignee/claim` and MCP `claim_thread` refuse a thread that is closed or archived with `409 thread-ended` (MCP `-32013`, `data.code` `thread_ended`) and a deleted one with `410 gone` (`-32014`), before the park, a block or the WIP limit is read. A thread closed as abandoned is not parked, so it could be claimed while closed. Both backends read the state in the claim's own transaction, so a close cannot land between the check and the claim.
- **Fixed:** a change delivery (the `github_branch` commit and draft pull request) queued before its task was cancelled, closed as abandoned, archived or deleted writes nothing to GitHub. The worker reads the thread just before its first GitHub call and settles the delivery as `skipped`, with a reason that starts `thread_ended`. A task closed some other way, as when its change landed, still delivers, and message relays and result replies to Slack, Linear and GitHub comments still go out, so a cancel's notice reaches Slack.
- **Changed:** `POST /threads/{id}/claim/acknowledge` and `POST /threads/{id}/claim/release`, and MCP `acknowledge_claim` and `release_claim`, answer a lease that expired, was taken over or was released with `409 claim-lost` (MCP `-32012`, `data.code` `claim_lost`), as `renew_claim` does, on the same lease clock and boot grace. They answered `404` (`-32004`), and an expired lease nothing had reaped yet was still acknowledged or released. A thread that does not exist is still `404`.
