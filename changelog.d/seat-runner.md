### Seat runner for session claimants

- **Added:** `examples/seat-runner/` keeps N session seats claiming, one task per harness run. Before each run it checks the host's load and free disk, polls the queue depth for its engine and repository, and runs the repository's preflight without the seat token or any other listed secret in its environment. All of that happens outside the harness sandbox. It then claims and acknowledges, and it starts no harness if the acknowledge fails or a stop arrives first. It runs the whole harness under `capped` and always releases the claim: on SIGTERM too, only after SIGTERM and then SIGKILL have ended every process the run started, and with retries if the server does not answer. The models a runner may start come from `[harness] models` in its config. A seat logs a network error or an unexpected error and carries on, and every run writes one JSON log line.
