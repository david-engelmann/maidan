### A workspace connects its own GitHub, Slack and Linear

- **Added:** a workspace can connect its own GitHub, Slack and Linear account with `PUT /workspaces/{wid}/connections/{surface}`, list them with `GET /workspaces/{wid}/connections` and remove one with `DELETE`, each with a console twin under `/ui/api`. The token is checked with the provider before it is stored, as an encrypted reserved secret no generic secret route or tool can read, and is never returned or logged. A workspace served by its own connection can bless a repository or channel, link a Slack channel or GitHub issue, watch a pull request and have results delivered, whether it was opened by sign-up, by the sandbox or by the operator. Storing a connection needs `FEDERATION_ENCRYPTION_KEY` on the instance.
- **Changed:** every send and read for a workspace now goes through one resolver. A workspace that stored its own connection always uses it, a workspace the operator opened with none of its own uses the server's credential when the server holds one, and any other workspace is served by nothing. The refusal reads `connect GitHub for this workspace first (Tools, Integrations)`. The egress worker, result delivery, the change sweep, pull-request reads, change outcomes, deploy ingest, the mark-ready and enqueue routes and the Slack and GitHub projectors all use it, and the egress worker runs whenever the instance holds a key to open workspace connections. The server's GitHub client keeps its `MAIDAN_GITHUB_WRITE_REPOS` list, and a workspace's own client is bounded by its allowlist and its token's permissions.
- **Added:** a workspace receives its own GitHub and Slack events on `POST /workspaces/{wid}/connections/github/webhook` and `POST /workspaces/{wid}/connections/slack/events`, verified with the secret it stored. An unknown workspace, a missing connection and a missing secret answer the same 404, and a delivery reaches that workspace's links and watches only. The console's webhook routes have twins under `/ui/api/workspaces/{wid}/webhooks`.
- **Changed:** a Slack channel link and a GitHub issue link belong to the workspace that made them, so two workspaces can link the same channel or issue and neither is told the other did. Migration 0243 rebuilds the keys. The server's own `/integrations/slack/events` and `/integrations/github/events` reach only the workspaces the operator opened that stored no connection of their own on that surface. A route that stores a workspace secret answers 503 naming `FEDERATION_ENCRYPTION_KEY` when the instance has none, where it answered 500.
- **Fixed:** a webhook made in the console now delivers. A browser session has no token to act as, and a webhook with none was revoked on its first matching event. The console now mints a token for the webhook, for the person who made it, holding only `workspace:admin` and `workspace:read`. Its secret is made and thrown away, and it is labelled `Webhook to <host> (id <webhook id>)` in the person's token list. The webhook ends when that person does or when the token is revoked. Revoking the webhook, from the console or by token, revokes the token minted for it and never one the person made. No route stores a webhook without a token.
- **Fixed:** a Slack or GitHub message for a workspace whose stored connection cannot be opened at routing time is queued, where it was dropped. The egress worker opens the connection again when it sends and retries or gives up. A queued result for a workspace nothing serves now ends its delivery row as failed, naming why. The pull-request refresh handed to MCP no longer keeps the state alive after it is dropped. The console's Webhooks and Connections panels remount on a workspace switch, and Webhooks refuses a second create while a signing secret is still shown.
