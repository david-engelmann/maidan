### Live streams show a member only what it may read, event by event

- **Fixed:** Any member could read every direct message in its workspace over `/ws/subscribe` or `/mcp/stream`, live and on replay, by naming the shared DM channel in `channel_grants`. A grant passed for that channel for anyone and nothing checked the conversation. Every event is now checked against the subscriber when it is sent, in replay, live delivery and the replay after a lag, by the rule the event backfill and webhook delivery already used. A DM's events go only to the conversation's participants.
- **Fixed:** A private channel made after a stream subscribed, a member removed from a private channel while subscribed, and the reactions, votes and mentions on a private channel's messages all kept reaching members who could not read that channel. The same per-event check covers them. A removal takes effect on a running stream within 5 seconds.
- **Changed:** `channel_grants` only narrows what a subscription asks for and never lends access. The AG-UI stream and webhook delivery use the same rule, so an event on a channel with no thread is no longer shown for the DM channel, and an event that names no workspace is never shown.
