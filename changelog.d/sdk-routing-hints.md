### SDK routing hints for self-hosted routers

- **Added:** every SDK gets `routing_hints` (`routingHints`, `RoutingHints`), which turns a thread and its parent into affinity headers for Dynamo (`X-Dynamo-Session-ID`, `X-Dynamo-Parent-Session-ID`), llm-d (`x-session-id`), AIBrix (`x-aibrix-session-key` with `routing-strategy: session-affinity`) and the SGLang router (`X-SMG-Routing-Key`). A child thread is keyed by its parent so it lands where the parent's prefix is warm; Dynamo (v1.6+, session affinity on) does that itself from the parent header. A routing key over 128 bytes (SGLang) or 256 bytes (AIBrix) is an error. Every SDK also gets `cache_salt(workspace_id, salt_key)`, a vLLM salt per workspace: `HMAC-SHA256(salt_key, "cache_salt\n" + workspace_id)` as unpadded base64url, with a server-side key of at least 32 bytes, so the salt cannot be computed from the workspace id. Set it from a trusted server-side component, never an end client; it is a cache partition, not an auth token. Both are hints, and the shared fixtures keep the four SDKs in step.
