### The server's GitHub, Slack and Linear credentials serve only the operator's workspaces

- **Security:** a workspace opened by sign-up or by the demo's sandbox can no longer aim the server's own GitHub, Slack or Linear credentials. Its admin could bless any repository or channel in its own egress allowlist, link a Slack channel or GitHub issue to a thread with no blessing at all, and watch any pull request. The server then read that pull request's checks and failing job log with its own GitHub credential, and delivered results and thread messages with its own Slack, GitHub and Linear credentials. The store now refuses these for any workspace whose origin is not `operator`, and treats an entry such a workspace made earlier as not blessed. A server that has sign-up on and holds `MAIDAN_GITHUB_TOKEN`, a GitHub App, `MAIDAN_SLACK_BOT_TOKEN` or `MAIDAN_LINEAR_API_KEY` should upgrade, and its operator should look for Slack and GitHub links made by workspaces it did not open.
